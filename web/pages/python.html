TECHNICAL GUIDES

Mechanics, tradeoffs and practice.

These are CODARIS editorial explanations. Occupational examples describe engineering responsibilities, not measured demographic shares.

Values, collections and mutability

Technical model

Lists and dictionaries are mutable containers; tuples and strings behave differently. Assignment binds a name to an object, so two names may refer to the same mutable value. Copying a container can be shallow rather than recursively independent.

Failure modes and decisions

Unexpected shared mutation is a common source of bugs. Decide whether a function modifies its input or returns a new value, and document that decision.

Practice task

Write a transformation that returns a new list and verify that the original list is unchanged.

items = ["C", "Python"]
updated = [*items, "SQL"]
assert items == ["C", "Python"]
assert len(updated) == 3

Functions and explicit validation

Technical model

A function should have a clear input and output contract. Type annotations describe intent to readers and tools but do not automatically validate runtime values. Reject invalid data at the boundary where its meaning is known.

Failure modes and decisions

Avoid mutable default arguments when you intend a fresh value for each call. Distinguish absent input from an empty but valid value.

Practice task

Implement a limit parser that rejects negative numbers and values above a documented maximum.

def parse_limit(value: str) -> int:
    limit = int(value)
    if not 1 <= limit <= 100:
        raise ValueError("limit must be between 1 and 100")
    return limit

Exceptions and resource cleanup

Technical model

Exceptions transfer control when an operation fails. Catch the specific failures you can handle, preserve useful context and let unexpected defects remain visible. Context managers help release resources even when a block raises.

Failure modes and decisions

A broad except that returns success can hide corrupt data or programming errors. Do not expose raw sensitive values in user-facing error messages.

Practice task

Read a file with a context manager and distinguish invalid JSON from a missing file in the caller.

import json
from pathlib import Path

def read_records(path: Path):
    with path.open(encoding="utf-8") as stream:
        return json.load(stream)

Modules and reproducible environments

Technical model

Modules organize code behind explicit import boundaries. A virtual environment separates installed packages from other projects; dependency records describe what another machine needs to reproduce the workflow.

Failure modes and decisions

A virtual environment does not pin every dependency automatically. Avoid relying on packages installed globally or on the current working directory being a particular location.

Practice task

Create a project environment and document the interpreter, dependency installation and command used to run the importer.

python -m venv .venv
# Activate with the command appropriate to your shell.
python -m pip --version
python -m unittest discover

Tests for behavior and boundaries

Technical model

Use concrete examples to establish expected behavior and negative cases to verify rejection paths. Keep pure transformation tests fast and separate filesystem or network integration from core logic where that boundary is useful.

Failure modes and decisions

A test should fail when its protected behavior breaks. Do not only test the happy path or assert a value calculated by copying the same algorithm under test.

Practice task

Test parse_limit with 1, 100, 0, 101 and non-numeric input. Explain the expected failure type.

import unittest

class LimitsTest(unittest.TestCase):
    def test_bounds(self):
        self.assertEqual(parse_limit("1"), 1)
        with self.assertRaises(ValueError):
            parse_limit("0")

Profiling and practical concurrency

Technical model

Measure the slow path before changing the architecture. I/O waits, CPU work and excessive allocations need different interventions. Async code helps coordinate waiting but does not make blocking operations or expensive computation disappear.

Failure modes and decisions

Do not assume a function is non-blocking because it is called from async code. Bound concurrent work and preserve cancellation and error handling.

Practice task

Time parsing and transformation separately on a representative dataset, then identify which stage is worth improving.

python -m cProfile -s cumulative importer.py
# Inspect cumulative time, then retest with representative inputs.

APPLY WHAT YOU LEARN

Build and verify.

Build a command-line reading-list importer that reads UTF-8 JSON, validates records, removes duplicates and writes a summary. Test empty input, missing fields, malformed JSON and inaccessible files.

Evidence to bring to a review

  • A precise description of the behavior and its boundaries.
  • Tests or observations covering success, invalid input and dependency failure.
  • A short explanation of one tradeoff and a known limitation.
  • Instructions that let another developer reproduce the result.

Examples illustrate individual ideas and are not a complete production application. Run experiments in a disposable environment and adapt them to the documented versions of your tools.
