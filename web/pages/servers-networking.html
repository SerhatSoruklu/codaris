Web Servers, Proxies & Networking.

A request may pass through DNS, transport security, proxies, load balancers and an application server before reaching business logic. Each hop can change routing, headers, buffering and timeout behavior. Trace the full path when diagnosing errors.

Roles and responsibilities.

How the pieces relate

                             → application → dependencies

TECHNICAL GUIDES

Mechanics, tradeoffs and practice.

These are CODARIS editorial explanations. Occupational examples describe engineering responsibilities, not measured demographic shares.

Origin server, reverse proxy and forward proxy

Technical model

An origin serves application content. A reverse proxy fronts one or more origins; a forward proxy acts on behalf of clients. Load balancing chooses an upstream, while caching may reuse a response without reaching that upstream.

Failure modes and decisions

Names overlap in products but responsibilities remain distinct. Document which component terminates TLS, handles authentication, buffers requests and owns each timeout.

Practice task

Draw a request path with two proxies and identify the component that can explain each possible 4xx or 5xx response.

https://nginx.org/en/docs/http/ngx_http_proxy_module.html ↗

DNS and endpoint changes

Technical model

DNS maps names to records that clients and resolvers may cache. A record change does not instantly move every client; propagation depends on caching and client behavior. DNS availability is part of service availability.

Failure modes and decisions

Plan migrations with cache behavior in mind and verify authoritative and recursive answers separately. A healthy server is unreachable if the name resolves incorrectly.

Practice task

Describe a low-disruption hostname migration and how you would distinguish stale DNS from an unhealthy new origin.

https://www.rfc-editor.org/rfc/rfc1034.html ↗

TLS termination and forwarded identity

Technical model

TLS protects a connection between endpoints; termination establishes where plaintext becomes visible. Proxies may add headers describing the original client or scheme, but those headers require an explicit trust policy.

Failure modes and decisions

Do not trust a client-supplied forwarding header as verified identity. Strip or overwrite untrusted values at the boundary and configure the application for the actual trusted proxy chain.

Practice task

Identify which hop is authorized to set a client-address header and test a request that spoofs it.

https://www.rfc-editor.org/rfc/rfc7239.html ↗

Timeouts, retries and request bodies

Technical model

Connect, read, write and total request deadlines cover different phases. A retry after a timeout can repeat work that the origin already performed. Buffering and body limits influence memory use and upload behavior.

Failure modes and decisions

Align deadlines across hops and avoid retrying unsafe operations without an idempotency design. Bound request sizes before consuming unbounded resources.

Practice task

Design timeouts for a request with a ten-second client budget and a dependency that occasionally stalls.

https://www.rfc-editor.org/rfc/rfc9110.html ↗

Load balancing and connection behavior

Technical model

Balancing may occur per connection or per request, depending on protocol and proxy design. Long-lived connections and uneven request costs can make simple request counts a poor indicator of load.

Failure modes and decisions

Health checks and draining matter during shutdown. Avoid sending new traffic to a terminating instance while existing work still needs time to finish.

Practice task

Compare balancing short HTTP requests with long-lived WebSocket connections and propose an appropriate draining policy.

https://www.haproxy.com/documentation/haproxy-configuration-tutorials/reliability/health-checks/ ↗

Network diagnosis with evidence

Technical model

Separate name resolution, connection establishment, TLS negotiation, HTTP response and application behavior. Tools that inspect each layer help avoid blaming application code for a lower-layer failure or the reverse.

Failure modes and decisions

A successful ping does not prove an HTTPS service works. Record timestamps, endpoint, protocol, response headers and correlation identifiers without exposing sensitive payloads.

Practice task

Build a troubleshooting sequence for a user reporting intermittent gateway timeouts. State what evidence would eliminate each hypothesis.

https://everything.curl.dev/ ↗
