# Security

Report vulnerabilities privately through this repository’s GitHub Security tab. Do not publish credentials, verification links or exploit details in public issues. If private reporting is unavailable, contact security support through contact@codaris.org without including secrets.

The implemented account service is C17 with libmicrohttpd, libpq, libsodium, libcurl and json-c. PostgreSQL is authoritative; the C/Wasm browser client never receives database or SMTP credentials. See [account design](docs/ACCOUNT-SERVICE.md) for the threat boundaries and [release runbook](docs/RELEASE.md) for deployment requirements. Implementation in this repository is not evidence of a completed live deployment.

Controls include Argon2id password hashes; random, hashed, expiring session tokens; HttpOnly/SameSite cookies with Secure in production; exact-origin JSON mutation requests; persistent request limits and proxy limits; single-use verification/reset tokens; reauthentication for email/password changes; database transactions and row locks; and an encrypted durable mail outbox. Avatars are constrained to fixed-size RGBA pixels, never executable file formats. External links are validated HTTPS claims, not proof of ownership. The original application reason is immutable in settings and the database.

The browser uses a restrictive Content Security Policy, disabled dynamic JavaScript evaluation in Emscripten, text-only DOM insertion, denied framing and an allowlisted public artifact. Session/account endpoints require server-side authentication regardless of the frontend’s visible state. Staff tools and shared chat are unavailable, not simulated authorization boundaries.

Production requires TLS, a least-privilege runtime database role, private secret configuration, monitored mail retries and provider limits, backups with verified restoration, and timely dependency security updates. The current API uses one polling thread; load testing and reverse-proxy controls are necessary for expected traffic. Windows runtime verification and public end-to-end delivery checks are separate from Linux local tests. No claim of immunity to XSS, denial of service or other attacks is made.
